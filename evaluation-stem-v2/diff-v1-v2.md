## 本轮新增发现

1. **并发修复不彻底**：负载下 1/5 轮仍出现单次失败（`results/p11-flakiness.json`）。上一轮只记录"Windows 锁竞争"，本轮给出量化：失败率从 3/5 降到 1/5，但未清零。
2. **`combine` 不检查条件一致性**：能源的"边界=使用阶段"与"全生命周期"、电子信息的"频点 A"与"频点 B"会被当成互补短板配对（`roles/energy.md`、`roles/electronics.md`）。
3. **`search` 不覆盖扩展字段**（`scripts/idea_card.py` 的 `command_search` 只搜 `FIELDS`）：`--set-extra 单位=mol/L` 之后搜"mol/L"搜不到。
4. **协议本身的预期错误**：P06、P14、P20 三条与实测不符，已如实记录在报告 §7，未修改判定表。
5. **文本层增益部分来自通用指令**：C1（三行规则）在 S1/S6 上已达 3/3，说明"分栏写作"不需要 Skill 语料。

## 两轮共同的未解问题

- 都没有真人研究生参与，都是 AI 角色扮演。
- 都没有跨模型、跨版本复测。
- 都无法验证"科学内容正确性"，只能验证结构与边界。
- 都只在 Windows + 单一 Python 版本上实测。
