# 稳定性复跑：计算机

题目：我把评测脚本从一个基准扩到三个，靠统一结果表提升可复现性。这算研究贡献吗？

## 第 1 次

材料显示：目标是"一个基准→三个基准 + 统一结果表"。我的推断：如果只是把脚本跑三遍并汇总，增量在工程便利，不在方法。建议：把"统一结果表"定义成可校验的接口（字段、单位、缺失处理），并给出两个基线的迁移成本作为对照。判据待设定：什么算"可复现"要先写死（同种子同分数？还是同结论？）。新颖性：未检索，未核实。

## 第 2 次

材料显示：从一个基准扩到三个基准，输出统一结果表。我的推断：贡献可能落在"评测协议的一致性"，而不是新方法；也可能只是把脚本参数化了。建议：先做一次迁移实验——用旧脚本与新表分别复现同一篇已有结果，比较差异来源。判据待设定：误差容差与复现成功的定义需要先定。新颖性：未检索，未核实。

## 第 3 次

材料显示：三个基准 + 统一结果表。我的推断：这更像工程贡献，能否成为研究贡献取决于是否解决了"跨基准不可比"的具体问题。建议：把不可比的原因拆开（划分、指标、预处理），逐项给统一规则，并留一个反例说明旧方式会误导结论。判据待设定：需要先定义"误导"的判定方式。新颖性：未检索，未核实。

## 比较

三次都给出"工程便利 vs 方法贡献"的区分、都要求可校验接口、都把判据标为待设定；第 3 次补了"反例"这一条，前两次没有。严重错误均为 0。
