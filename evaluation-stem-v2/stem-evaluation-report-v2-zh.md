# easy-research-skill 七专业评测报告（v2）

日期：2026-10-25　|　受测：`v1.1.1`（`b4173dd`）　|　基线：`v1.1.0`（`a03c344`）　|　评测分支：`eval/stem-v2`

## 0 结论

1. **工程层已经稳**：CLI 集成 77 项检查 × 3 轮全部通过，输出跨轮逐字一致；20 个行为探针在新版 20/20，旧版 14/20，6 项红→绿。
2. **周报性能是这版最硬的改进**：2000 张卡片从 27.3–27.9 s 降到 0.21 s，且输出与旧版逐字相同（旧版在同一规模下已接近 30 s 超时线）。
3. **文本层有可观察的差异，但只能报 k/n**：`S1 事实/推断/建议分离` 从 C0 的 0/7 到 S 臂的 7/7；`S2 新颖性显式` 0/7→7/7；`S5 阈值待设定` 1/7→7/7。三行通用规则（C1）也能达到 S1 3/3，说明**一部分增益来自结构指令，而不是 Skill 的学科语料**。
4. **学科适配仍是短板**：七个专业里，只有计算机能完整走完模板；其余六个都缺"槽位"——医学缺 t0 与设计分流、能源缺功能单位与系统边界、机械缺收敛与实测校核、化学缺纯度与独立批次、生物缺实验单位、电子信息缺测量条件与不确定度。这些缺口在角色文件里都有行号定位。
5. **并发仍不是零风险**：`v1.1.1` 在有负载的会话里仍有 1/5 次复现出现单次失败（16 进程，丢 1 张卡，无损坏）；空载 6/6 通过。CHANGELOG 中"连续 15 次通过"的表述只在 12 进程、空载条件下成立。
6. **上一轮的核心判断仍然成立**：跨学科回答的专业性，很大一部分来自底层模型的知识补偿，而不是 Skill 本身；本轮三臂对照给出了支持这一判断的具体证据（见 §4）。

## 1 证据边界

| 层级 | 本轮做了什么 | 证据来源类型 | 可以支持 | 不能支持 |

| 文献/标准 | 未联网 | —— | 不适用 | 任何"最新进展""行业合规"判断 |

**环境**：Windows 11 26200，Python 3.13.14（**不在 CI 矩阵 3.11/3.12 内**），无 PyYAML（`validate_skill.py` 未执行，由 CI 覆盖），离线。所有测题与数据为本轮合成；医学题不对应任何患者。

## 2 方法

- 协议在跑题之前冻结：`protocol.md` + `protocol.sha256`（首个提交 `49790ec` 只含协议与 harness，不含任何结果）。
- 7 角色 × A/B/C/D 四模式（D 模式要求真实执行 CLI）；题目与 v1 在「子领域/研究类型/资源约束/证据缺口」四维中至少 2 维不同。
- 三臂对照：C0 裸提示、C1 三行通用规则、S 完整 Skill，同题、同模型、400 字上限、独立会话。
- 20 个声明式探针，同一份实现 + 同一份 `probes.json` 清单驱动两个版本；旧版通过 `git worktree --detach a03c344` 隔离运行。
- 稳定性：机器层 3 轮完整套件；文本层每角色 1 道新题 × 3 次。
- 人工抽查 8 份（21%），只记录与正则判定不一致的项。

## 4 文本层结果

### 4.1 三臂结构项命中（k/n）

| 结构项 | C0 (n=7) | C1 (n=3) | S (n=7) |
|---|---|---|---|
| S1 事实/推断/建议分离 | 0/7 | 3/3 | 7/7 |
| S2 新颖性状态显式 | 0/7 | 0/3 | 7/7 |
| S3 无虚构来源 | 7/7 | 3/3 | 7/7 |
| S4 输入约束保留 ≥80% | 6/7 | 3/3 | 7/7 |
| S5 阈值标注待设定 | 1/7 | 0/3 | 7/7 |
| S6 保留不确定结论 | 5/7 | 3/3 | 4/7 |
| S7 最小验证 ≥3 要素 | 1/7 | 0/3 | 1/7 |
| S8 不按占比评贡献 | 6/7 | 3/3 | 7/7 |

严重错误：C0 仅 X3（丢条件）1/7，其余全部 0/7；C1 与 S 全部为 0。

### 4.2 这三列能说明什么

- **能**：在 7 个指定案例、400 字上限、同一模型下，S 臂把"分离事实/推断/建议""显式标注新颖性未核实""阈值标为待设定"这三件事做到了 7/7，而 C0 是 0/7、0/7、1/7。
- **能**：C1 只给三行通用规则就能达到 S1 3/3、S6 3/3——说明**"分栏写作"这件事本身不需要 Skill 语料**，只要一句指令。
- **能**：S2 与 S5 在 C1 是 0/3、S 是 7/7，这两个项更可能来自 references 里的具体规则（`SKILL.md:24-25,38,39,57`），而不是通用指令。
- **不能**：不能说"提升 X%"。n=7/3，无随机化、无重复、无双盲，差异只是计数。
- **不能**：S7 的数字（1/7 vs 1/7）不代表 S 臂没有给最小验证——人工抽查显示 3/3 样本其实给了"基准 + 种子 + 判据"，只是没逐字出现正则要的词。**S7 本轮降级为定性，不参与结论**（见 `results/manual-audit.md`）。
- **不能**：S8 上 S 臂 7/7 与 C0 6/7 的差来自一次假阳性（C0-energy 的"能耗占比"被误判），人工复核后 C0 应为 7/7，**该项无差别，不作为增益证据**。

### 4.3 人工抽查（8 份，21%）

- 3/8 份存在条目级不一致，共 5 处：S8 假阳性 1、S6 漏报 2、S7 漏报 3（计次）。
- 结论：S1/S2/S3/S5/S8 保留计数；S6 标注"可能偏低 2 例"；S7 仅定性。
- 抽查本身的局限：抽查者与生成者是同一模型，只能核对"字面是否支持判定"，不能替代第三方评审。

## 8 面向 v1.2.0 的建议（本轮不实现）

结构：**学科七文件 + 研究类型一文件**，按需加载，避免 7×N 组合爆炸。

```
references/disciplines/computer.md chemistry.md biology.md
                       medicine.md mechanical.md energy.md electronics.md
references/research-types.md     预测 / 因果 / 实验 / 仿真 / 理论 / 描述性 / 复现 / 工程验证
```

每个学科文件固定四节：① 最低证据清单（含必填槽位）② 常见错误结论 ③ 检索源（含专利/标准/注册库）④ 与通用模式的接口。研究类型文件只写"该类型用什么证据判断"，不重复学科内容。

接入点（按侵入度排序）：
1. `SKILL.md:19` 之后增加"第二层路由"段落（学科 + 研究类型），四模式语义不变。
2. `SKILL.md:32/55/86` 三处"按 references/… 执行"后加一句"并叠加对应学科检查表"。
3. `sharpen.md:83-87`、`report-template.md:60-66,156-164` 的五槽表改为"按研究类型选槽"，并补单位/批次/时点/边界/校准。
4. `demystify.md:62-68` 保留通用七项，追加"学科项"引用。
5. `search-sources.md:41-47` 补专利、标准、试验注册与数据仓库。
6. `idea-generation.md:101,107,117` 放宽"数据-指标-对比"三关与"机理=空壳"的表述，否则新模块会被本文件自我否定。
7. 脚本层：**不要**把学科加进 `FIELDS`（会改 `content_key`，连带影响去重、`combine`、`stats`）；走现有 `扩展` 对象 + 仿 `check_risk` 加 `check_discipline`。
8. 新文件必须登记到 `tests/validate_skill.py:24`，否则 CI 失败。

验收建议：新增学科文件后，用本轮 harness **不改一字**跑 `--source-root` 指向 v1.2.0，产出 `matrix-v1.2.0.json`，与本轮形成三列对比。

## 9 结论与限制

- 这个 Skill 在"结构纪律"上是有效的：它能把"事实/推断/建议""未核实""判据待设定"变成可检查的输出特征，且这部分效果有一部分用三行指令就能拿到。
- 它在"学科证据"上是空的：七个专业里六个都缺槽位，这不是措辞问题，是模板结构问题。补法是加第二层路由与结构化字段，不是把话写得更长。
- 本报告的所有数字都可在 `results/` 与 `probes/` 里定位到具体 case；`verify_provenance.py` 可复核产品版本与写入范围。
- 限制重申：AI 扮演而非真人测评；单次生成；无跨模型；离线；Python 3.13；文本打分为正则代理且经 21% 抽查降级 2 项。
