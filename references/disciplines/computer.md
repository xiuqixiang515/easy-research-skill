# 计算机（方法改进 / 复现 / 基准审计）

> 加载条件：识别到学科为计算机时加载；与 `../research-types.md` 中对应的研究类型段叠加。
> 这是检查清单，不是行业标准；不能据此声称"符合某某规范"。

## 1 最低证据清单（必填槽位）

| 槽位 | 必填 | 要问的问题 | 缺失时的后果 |
|---|---|---|---|
| 数据切分单位 | 是 | 按样本、用户、时间还是实体切？同一主体是否跨集合？ | 同源泄漏会让指标虚高，且无法事后修正 |
| 泄漏路径 | 是 | 预处理、特征选择、调参、早停分别用了哪个集合？ | 无法判断提升来自方法还是信息泄漏 |
| 随机性 | 是 | 种子数、是否报告每次结果与方差？ | 单次差值无法区分方法差异与运行波动 |
| 算力预算 | 是 | 基线是否在同参数量/同步数/同搜索预算下重训？ | 比较不对等 |
| 指标口径 | 是 | 主指标定义、是否 macro、是否含拒识；测试集是否参与任何选择 | 指标不可比 |
| 环境与版本 | 建议 | 依赖版本、驱动、代码 commit | 他人无法复现 |
| 分布与工况 | 建议 | 测试分布与部署分布差在哪 | 结论外推无依据 |

## 2 常见错误结论

| 错误结论 | 为什么错 | 追问 |
|---|---|---|
| "在 3 个基准上各涨 0.4，说明普遍泛化" | 0.4 可能小于种子波动；且若早停/调参在测试集上，差值含选择偏差 | 用验证集重选超参后差值还在吗？几次种子的极差是多少？ |
| "换了更强的 backbone，贡献是新模块" | 增益可能来自容量或预训练数据 | 同 backbone、同预算的基线对照做了吗？ |
| "消融掉模块后掉了 2 分，模块有效" | 单次消融无法分离交互效应与噪声 | 每种配置几次种子？掉分是否超过极差？ |
| "我们首次提出 X 任务" | 同名工作可能在不同社区 | 检索了哪几个库、什么词、什么日期？ |
| "代码开源即可复现" | 环境、数据划分、随机性未固定时不可复现 | 一条命令能跑出表里的数吗？ |

## 3 检索源

| 用途 | 入口 | 注意 |
|---|---|---|
| 预印本 | arXiv（cs.*、stat.ML） | 按提交时间排序；预印本未评审 |
| 会议/期刊 | DBLP、会议官网 proceedings | 查"是否首次"优先看同会议的近两届 |
| 引用关系 | Semantic Scholar、Google Scholar | 引用量不代表正确性 |
| 代码与结果 | Papers with Code、作者仓库 | 仓库与论文版本可能不一致 |

无法访问时明确写"未检索"，不得据记忆断言"没人做过"。

## 4 与四模式的接口

- **A 找 idea**：候选卡必须填"数据切分单位"和"算力预算"两格；做不到就把该候选标为"资源不足"，不要写成待验证。
- **B 拆论文**：除通用七项外，加查三条——测试集是否参与选择、基线是否同预算、方差是否报告。
- **C 淬炼想法**：最小验证先做"负对照"（关掉改动 / 用同预算基线），再做增益比较；判据用"超过种子极差"而不是固定分数线。
- **D 素材库**：`--set-extra 学科=计算机 --set-extra 研究类型=复现 --set-extra 切分=按用户 --set-extra 种子=3`

## 5 自查

1. 我能一句话说清"在什么切分、和谁同预算、几次种子"吗？
2. 我的增益是否超过了种子极差？
3. 有没有任何一步用了测试集？
4. 基线是不是我重训的、而不是抄来的数？
5. 换一个分布，结论还成立吗？不成立就写明边界。
