# 检索策略（跨领域通用）

目标：确认一个 idea 有没有人做过，并拿到足够素材做对比。**必须实际检索，不能凭记忆断言。**

## 三层检索

### 第一层：宽搜（确认方向热度与主要团队）

用 2–3 个核心术语，不加限定词。目的不是找精确匹配，而是了解：

- 这个方向近两年有没有人在做
- 主要来自哪些组
- 常用术语是什么（**术语是后续检索的关键**）

读 5–10 篇的标题和摘要即可，不深入。

### 第二层：精搜（找最接近的工作）

换 3 组关键词：

| 组 | 构成 | 例 |
|---|---|---|
| 核心 | 问题词 + 方法词 | "small sample" + "cross-domain" |
| 同义 | 换成领域内的其他叫法 | "few-shot"、"low-resource"、"data-scarce" |
| 反向 | 反过来说 | "domain shift generalization without target data" |

**术语替换是最容易被忽略的一步。** 同一个问题在不同社区叫法完全不同（统计叫"分布偏移"，机器学习叫"domain shift"，医学统计叫"外部验证"）。只用一个词搜，很容易误判"没人做过"。

### 第三层：反向追溯（找源头与分叉）

对找到的最相关的 2–3 篇：

- 看它的参考文献里被反复引用的那几篇（源头工作）
- 看在 Google Scholar / Semantic Scholar 上「引用它的文章」（后续分叉）
- 看最新综述的相关章节（**综述是找缝隙最快的方式**，因为综述的本职就是列 gap）

## 检索源选择

| 场景 | 首选 | 说明 |
|---|---|---|
| 预印本、最新工作 | arXiv、bioRxiv、medRxiv、SSRN | 按提交时间排序，近 3 个月最有用 |
| 正式发表、跨学科 | Google Scholar | 覆盖面广，但需人工过滤 |
| 计算机领域 | DBLP（查会议）、Semantic Scholar（查引用关系） | DBLP 权威，S2 的引用图好用 |
| 生命科学 | PubMed / Web of Science | 用 MeSH 词表提高召回 |
| 材料化学 | Web of Science、Scopus | 关键词 + 学科限定 |
| 工程/物理 | IEEE Xplore、APS、INSPIRE | 按领域选 |
| 中文文献 | CNKI、万方 | 部分方向国内工作更集中，别漏 |

**检索可用性：** 先确认当前是否能访问目标检索源。无网络、权限墙、检索接口不给命中数或全文不可读时，记录阻碍和已查看范围；可用的公开来源作为补充，但不要声称覆盖付费数据库。新颖性标为未核实。

**跨领域提示：** 用户给的方向可能横跨两个社区（如"AI + 材料"）。这时**两边都要搜一遍**，因为同一个人群可能不知道另一半的工作，而这恰恰是你建立新颖性的机会——但也要小心，可能是"两边都试过且失败了"。

## 判定新颖性

对每个候选 idea，给出明确档位：

| 档位 | 含义 | 行动 |
|---|---|---|
| 完全相同 | 有人做过同样的事 | 不放弃：读它，找它的短板，转为改进或换设定 |
| 高度相近 | 思路一致但设定/规模/数据不同 | **最理想的落点**，明确说清差异 |
| 部分重叠 | 覆盖了部分环节 | 缩小范围，只做未被覆盖的那部分 |
| 未发现 | 没有直接相关工作 | 谨慎：问"为什么没人做" |

关于最后一档，必问三句：

1. 是不是术语不同导致的假阴性？（再换 2 组词）
2. 是不是因为没价值？（问用户实际场景）
3. 是不是因为已知不可行？（看有没有明确指出这条路不通的工作）

## 记录格式

检索记录要留档，写进报告附录：

| 日期 | 关键词 | 检索源/链接 | 时间范围 | 命中数或不可得 | 查看范围 | 最相关工作及差异 |
|---|---|---|---|---|

**关键词必须原样记录**，方便下次复盘时复用或调整。

## 常见错误

- **只搜一个词就下结论**：召回率极低，误判"没人做过"
- **只看近一年**：可能错过了更早的同名工作，或被放弃后又重新被提起
- **只看标题**：很多相关工作的标题不含你的关键词，摘要和结论里才有
- **忽略中文文献**：部分方向国内团队是主力
- **检索完不记录**：下次从头再来，浪费且不可复现
