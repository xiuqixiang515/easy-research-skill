## 2 题 A

### 题目

只有 4 张 3090 和一批未标注运维日志，做日志异常检测，给方向与最小验证。

### 原始回答

【材料显示】`computer.md:10-14` 要求五个必填槽位；`SKILL.md:40` 规定槽位缺失时结论降级为"信息不足"；`computer.md:43` 要求判据用"超过种子极差"。`research-types.md:6-19` 的十类里没有"无标注"这一类。

【我的推断】这个任务实为"预测 + 工程验证"跨类型：既要时点与验证范围（§1），又要告警预算与工况覆盖（§8）。它不属于方法改进。

方向，按成本排（合成示例，非文献结论）：

1. 计数基线：日志解析成模板 + 时间窗计数 + IsolationForest / PCA。3090 基本不用。**先跑通，作为后面所有方法的对照。**
2. 序列自监督：模板序列的 masked prediction 或 next-template，参数量压到 10M 以内，单卡够。四张卡的价值在并行跑种子与消融，不在堆模型。
3. 表征 + 距离：预训练编码器出句向量，按实体建"正常画像"，偏离度打分。冷启动实体单独一路。

【建议】先 1，再 2 的单种子。别一上来训大模型，会在没有基线和没有标签的情况下产出无法解释的分数。

标签从哪来——这是本题真问题。三条路，成本递增：

- 工单/告警回捞：把历史 incident 时段当正例，窗口对齐。有偏，只覆盖"被发现的"异常。
- 注入合成异常：在留出的正常段按类型注入（模板缺失、顺序错乱、频率突增）。只能证明"能抓这类注入"，不能证明线上有效，报告里必须写死这句。
- 人工盲标：抽 300–500 个窗口，算区间。异常率未知时区间会很宽，别拿点估计下结论。

最小验证（一周量级）：

- 切分：按时间切（前 70 / 后 30）**并且**按实体切（同一主机或服务不跨集合）。两条都做，日志同时有时间与实体两种泄漏路径。窗口长度待设定：候选 5min / 30min / 1h，用验证集选。
- 指标：PR-AUC 为主，辅助 recall@k 与"每天告警条数"。异常率未知时 F1 不可比，不用。
- 阈值：待设定。选法是先定运维能处理的告警预算（每班 N 条，N 由值班人力决定，现在未知），在验证集取满足预算的阈值，冻结后测试集只跑一次。
- 随机性：≥3 个种子，报极差。增益要超过极差才算数。
- 负对照：时间戳打乱后重训一遍。若指标不掉，说明模型学的是结构或泄漏，不是异常。
- 算力：4×3090 够用，瓶颈是标注与切分，不是卡。

【尚未核实】模板稳定性、异常占比、是否有 incident 记录、采集是否连续。四项任一不成立，方案要改。所以第一步不是建模，是半天数据体检：每日条数曲线、模板数随时间变化、实体数、缺失段。

### 槽位自检

- 已填：数据切分单位（时间 + 实体双切，并说明为何两条都要）、泄漏路径（预处理只在训练段 fit，阈值只在验证集选）、随机性（≥3 种子报极差）、指标口径（PR-AUC，明确不用 F1）。
- 部分填：算力预算——只说明四卡够用，未给出基线重训的 GPU-hours 与搜索预算对等方案，因为日志规模未知。
- 未填：环境与版本、分布与工况（均为建议槽位）。手上没有部署环境与线上分布信息，只能标"尚未核实"，不用推测填满。

## 3 题 B

### 题目

合成摘要：自有数据集 F1 0.91、公开数据集 0.72，称"方法通用"；未报划分、预处理、基线预算。评估主张。

### 原始回答

【材料显示】`SKILL.md:76`：只有摘要时只能分析摘要主张，缺的事实标"无法判断"。`computer.md:42`：B 模式另查测试集是否参与选择、基线是否同预算、方差是否报告。

三条主张得拆开，混在一起谈会被 0.91 带走。

1. "自有 0.91"——【我的推断】这是全篇最可疑的数。自有数据集通常是被反复看过的那份：调参、早停、阈值、预处理只要有一处碰了全量或测试集，0.91 就不可复现。摘要三样都没写，按 `computer.md:11-14` 是五个必填槽位全缺，这条只能判"信息不足"，不能当性能证据用。
2. "公开 0.72"——这个数反而更可信，因为外部数据不受作者调参影响（前提是预处理没在公开集上重做、阈值没重校准）。但 0.72 也可能是低估：域偏移、标签口径不同。方向不确定。
3. "方法通用"——【我的推断】这是全篇唯一真正的科学主张，也是最不成立的。通用性至少要：≥3 个来源不同的公开集、同一套冻结流程、同预算基线、每集报区间。现在只有 1 个自建 + 1 个公开，而公开那个低 0.19。**如果协议公平，这 0.19 恰恰是"不通用"的证据，不是补充说明。**

缺口的组合才要命：无划分方式 → 排不掉泄漏；无预处理流程 → 判断不了 0.72 是否同一 pipeline；无基线预算 → 排不掉"赢在算力"。三者叠加时，0.91 与 0.72 的差既不能归因于数据集难度，也不能归因于方法强。0.19 是否超过种子极差，未知。

【建议】可辩护的下一步：向作者要切分脚本、预处理的 fit 范围、基线重训日志。要不到就自己按实体/时间重切、三个种子、同预算重训基线再比。在那之前，把"通用"改写成"在一个自建集与一个公开集上报告了结果，泛化性未验证"。

【尚未核实】公开集名称、两集标签定义是否一致、0.72 的阈值来源、0.19 相对种子极差的大小。

### 槽位自检

- 部分填：指标口径——有 F1 数值，但未定义 macro/微平均、正类、阈值来源，故只算"报了个数"，不算口径清楚。
- 未填：数据切分单位、泄漏路径、随机性、算力预算四项必填槽位，原因是摘要确实没写。按 `SKILL.md:40` 写"信息不足"，而不是替作者补一个合理默认。
- 未填：环境与版本、分布与工况（建议槽位），摘要未提。

## 4 题 C

### 题目

把在线学习改成每夜全量重训，理由"更稳定"。检验这个想法。

### 原始回答

先拆"稳定"，否则无法检验。四种意思：统计稳定（换种子不跳）、运行稳定（相邻两天分数分布不突变）、可复现（同批数据重放出同一模型）、服务稳定（延迟吞吐）。【我的推断】你要的是第二种，全量重训改善的是第三种。分歧就在这。

逐条检验：

1. 不成立的一半：重训把模型换成"最近一段数据的解"。滑窗丢长尾，跨夜分数出台阶；全历史则训练集天天变，"稳"只是训练集变化小，不是方法稳。让在线学习抖的是学习率、样本顺序、类别极不平衡、反馈回路——数据管道不变，全量重训一样躲不掉。
2. 成立的一半：每天一个完整产物，可回滚、可审计、可离线复算。这是真优势，但它叫可运维性，不叫稳定性。
3. 成本：四卡每夜全量，训练时长随数据线性涨，某天会溢出夜间窗口。上限未知，先测"数据量—耗时"曲线。

【建议】别二选一，做三臂：在线 / 每夜全量 / 冻结不更新。第三臂是关键负对照——若"稳定"只是"不变"，冻结最稳，但会随漂移失效。没有它，"更稳定"不可证伪。

判据（全部待设定，附选法）：

- 日间分数分布距离（PSI 一类）：阈值取基线两周的自然波动上界，不是拍一个 0.1。
- 每日告警量：阈值取运维预算。
- 延迟标签上的 PR-AUC：观察窗 ≥ 标签回填周期。
- 注入一次已知漂移，看恢复天数。**这是唯一能直接测"稳定性"的实验。**
- 时长至少覆盖一个业务周期，两周起步；只跑一周会把周期效应当成方法效应。

【我的推断】三臂在延迟标签上打平，就选运维成本最低的那臂。稳定性是约束，不是目标。

【尚未核实】现有更新方式（增量 SGD？滑窗？）、标签回填延迟、夜间窗口长度、数据日增量。

### 槽位自检

- 已填：随机性（三臂各 ≥3 种子报极差）、算力预算（要求同预算重训，并先测耗时曲线确认夜间窗口可行）、指标口径（PR-AUC + 告警量 + 分布距离，阈值全部待设定并给出选法）、分布与工况（注入漂移、跨两周覆盖）。
- 部分填：数据切分单位（写了时间外切分，未定实体维度）、泄漏路径（阈值是否只用训练段未交代，因为不知道现有管道）。
- 未填：环境与版本，未取得现有系统的依赖与部署信息。

## 6 规则缺口

1. `SKILL.md:35` 要求按研究类型补槽位，但 `research-types.md:6-19` 的十类里没有"无标注/弱监督"。题 A 的标签来源无处安放，只能自己造一套注入协议。

3. `SKILL.md:23` 说"识别后各加载一份"，但路由表（`SKILL.md:25-33`）只列学科文件，类型文件只在正文提了一句。B 模式真正的检查项在 `SKILL.md:71` 指向的 `demystify.md`，不在路由表内，文件分层不自足。
