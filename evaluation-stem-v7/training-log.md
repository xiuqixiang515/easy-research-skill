# 「训练」记录：冲突检测阈值调参

日期：2026-10-25　|　产品：`v1.6.2`（`fc8df49`）　|　分支/标签：`eval/stem-v7` / `eval-stem-v7`
方案：`protocol-training.md`（先于运行写定）

## 0 结论

1. **当前产品常量已在最优平台区**（θ=0.40 / m=5 / s=2）。81 组网格里，训练宏 F1 最高 0.850，由 **24 组配置并列**（θ∈[0.35,0.50]、m∈{3,5,8}、s∈{1,2}）；按"与当前参数最近"的仲裁规则，选中的就是现值。
2. **因此不改产品代码**。这也符合方案 §7 的停止条件：最优等于现值，不改。
3. **θ 的可用区间是 [0.35, 0.50]**。低于 0.3 时项目标签被判成"通用"，召回崩到接近 0；高于 0.5 时覆盖一半项目的主题标签漏网，查准掉到 0.51–0.66。
4. **天花板来自数据，不来自阈值**：不填「项目」时，稀疏标签族的 F1 上限只有 0.40；歧义噪声族上限 0.81。这两族里，任何 θ 都救不了。
5. 真正能提升的杠杆是**把「项目」填上**——这已经是模板与文档的推荐做法，本轮不新增规则。

## 1 目标与设定（方案摘要）

- 目标：留出测试族上最大化 F1
- 约束：测试精度 ≥0.90；2000 卡周报 ≤1.0 s
- 超参：θ（`GENERIC_TAG_SHARE`）、m（`GENERIC_MIN_CARDS`）、s（退化阈值）
- 空间：9 × 3 × 3 = 81
- 数据：4 训练族 + 1 验证族 + 1 压力族 + 2 测试族

| 族 | 形态 | 卡数 |
|---|---|---|
| F1_dense | 填了项目字段，4 项目/学科 | 120 |
| F2_sparse | 不填项目，项目标签只在一半卡片 | 96 |
| F3_umbrella | 不填项目，主题标签覆盖 4/8 项目（50%） | 96 |
| F7_few | 不填项目，只有 3 个项目（项目标签 33%） | 30 |
| F6_noisy | 验证：噪声标签覆盖 2/4 项目（50%，可分） | 120 |
| F6_ambiguous | 压力：噪声覆盖 3/4 项目（33%，与项目标签同频） | 120 |
| F4_tiny | 测试：每学科 3 张卡 | 12 |
| F5_cross | 测试：项目名跨学科复用 | 60 |

### R82 选择（验证族 F6_noisy）

## 3 结论与解读

**为什么当前值是最优的？**
θ=0.40 落在平台区正中：往下 0.35 开始有项目标签被误判的风险，往上 0.45 仍然安全但收益为零（平台已到顶），0.55 之后主题标签漏网。m=5 与 s=2 在"真实规模"的族上不触发，触发时（极小库、标签退化）恰好是想要的行为。

**天花板在哪？**
两个族暴露了规则的能力边界：
- F2_sparse（不填项目 + 一半卡片没有项目标签）：F1 上限 0.40 —— 标签缺失时没有信息可用。
- F6_ambiguous（噪声标签 33%，与项目标签 25% 同频）：F1 上限 0.81 —— 单一频率阈值无法区分"跨项目通用标签"和"项目专属标签"。

这两条都不是调参能解决的，只能靠**数据侧动作**：填「项目」、别用跨项目的泛标签。

**要不要因此改产品？**
不改。方案 §7 写明了停止条件，本轮结果落在"最优=现值"。真正有价值的产出是这条边界说明：**填了「项目」的库，精度 1.000；不填且标签稀疏的库，上限 0.40**。

## 4 过程中的四次自身返工（照实记）

1. **参数名不一致**：`CURRENT` 用 `max_signatures`，函数签名写 `max_sig`，第一次运行直接 TypeError。
2. **真值绑在可选字段上**：`_proj` 取自「项目」字段，不填字段的族被当成"整个学科一个项目"，全族 F1 假性为 1.0 或 0.05。改成构造时单独记真项目。
3. **约束不可行导致选错**：精度 ≥0.90 是硬约束，而验证族精度上限 0.862，于是只剩 θ=0.2 能进门（F1 0.148）——差点得出"应该把 θ 调到 0.2"的错误结论。改成"训练竞争 + 验证 F1"的两段式，并如实记录约束未达成。
4. **替换时括号没闭合**：改选择逻辑时删掉了 dict 的收尾 `},`，整个脚本 SyntaxError。

四次都是**测量代码的错**，不是产品代码的错。调参这类工作里，测量代码出错比模型出错更常见。

## 5 局限

- 全部是合成族，标签分布由我设定；真实库的标签习惯未知。
- 只有 8 个族、一次划分；F1 的置信区间很宽，0.02 的"训练竞争"阈值是经验值。
- 精度约束 0.90 是我定的，本轮证明它在噪声族上不可行，但没有和用户确认应该定多少。
- 只搜三个参数；冲突字段集合、200 条上限、项目优先的判定顺序都没搜。
