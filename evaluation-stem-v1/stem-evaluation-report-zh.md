# Easy Research v1.1.0 七专业适配评估报告

日期：2026-10-24。对象：本地 Git 标签 v1.1.0（a03c344）的源码副本。本轮仅增加评估材料，不修改 Skill 正文、references、业务脚本或原始 ZIP。

## 结论

当前版本具备可复用的科研问题整理、证据分层和素材管理基础，但还不能据此宣称“已验证适合理工科七专业”。它较接近计算机方法研究的工作流；跨学科回答的专业性，有一部分来自底层模型的知识补偿，尚未成为 Skill 可重复保障的行为。

建议保留 A 找 idea、B 拆论文、C 淬炼想法、D 素材库四种任务模式，增加“学科 + 研究类型”两条路由，再按需加载检查表。优先修规则冲突与导入丢字段，再扩学科覆盖。

需要纠正上一份修复验收报告的结论：其中“未发现新的互相矛盾或无法执行的硬性要求”表述过宽。本轮找到 report-template 和 sharpen 中的残留冲突。原先21项脚本测试通过，不能证明科研规则一致或跨学科有效。

完整角色记录分别保存为 computer.md、chemistry.md、biology.md、medicine.md、mechanical.md、energy.md、electronics.md。应结合这些原始输出判断“模型做到了什么”和“Skill明确要求了什么”。

## 3. 四个评估维度

### 有效性：有助于组织研究，但专业证据要求不全

主文件要求事实/推断/建议分开、不给未检索的新颖性结论、列最小实验，这些结构可以跨专业复用。A/B/C模板较适合“改进方法并对比性能”，但基础理论、探索现象、描述研究、独立复现、工程失效分析也可能有价值，不应以“有无某人受损/强基线/已知失败机制”作为统一准入条件。

角色回答能识别案例里的明显证据缺口，不等于Skill本身让模型新增了这些专业能力。还需加入未提示风险的隐藏测试、无Skill对照，以及学科评审。

### 效率：脚本小库可用；Agent效率没有测量

实际周报计时（每种规模仅1次；包含Python进程启动、输出生成与捕获）：

|合成卡片数|实际秒数|退出码|结果|
|---:|---:|---:|---|
|100|0.242|0|生成成功|
|500|1.643|0|生成成功|
|1000|6.317|0|生成成功|

report_render.py 的 weekly_report 遍历所有卡片对，反复计算内容指纹并保存标签组合对应的卡片对；这是静态可见的二次增长路径。上述3点不构成严谨性能曲线，未测内存、并发和大于1000张的规模。

专业适配后，应按需只加载相关学科/研究类型检查表，提供快速评估与完整评估两种输出深度。完整多表格输出不一定节省用户时间；需在真人试用中测“达到可用研究计划的时间”，而非单看字数。

### 可靠性：证据规则有价值，但仍有冲突与静默丢字段

本轮75项程序判定，73项符合预设条件、2项未符合；其中包含68次真实CLI命令和7项周报重复一致性比较。这个比例仅描述这批程序检查，不能当作科研建议正确率。

七专业常见科学字符串（F1、mol/L、K、ΔCt、AUC区间、MPa、kWh、η、MHz、BER等）作为既有“问题”字段内容可逐字保存和查看。脚本只存储文本，没有进行量纲、数值或科学有效性验证。

两个新失败详见下节：Markdown风险枚举绕过、未知专业字段静默丢弃。

### 稳定性：本地确定性流程通过；模型行为未充分测试

每专业同一数据库生成3次周报，移除生成时间后内容一致，7/7组符合预设条件。每专业重复导入被拒绝且库哈希不变。不同专业素材的存储路径表现一致。

本轮未做同一科研问题的多随机种子、多模型、多版本、提示改写或上下文中断恢复测试。21个角色案例不是每题三次复测。跨轮长任务的状态恢复、目标Agent的技能触发及Windows以外的平台仍待验证。

## 4. 问题、根因、建议与验收

P1：可能系统性扭曲科研证据判断，优先处理。P2：功能、数据完整性、专业适配或效率有实质缺口。这里的科研规则风险不等同于软件安全漏洞。

### S01｜P2｜实测：Markdown风险字段绕过CLI枚举

复现：在 temp-data/bad-risk.md 写入“## 风险校验”“- 问题: synthetic”“- 风险: 极低”；执行：
~~~powershell
python -X utf8 scripts/idea_card.py --db evaluation-stem-v1/temp-data/probes.json add --file evaluation-stem-v1/temp-data/bad-risk.md
~~~
预期：退出2，明确说明只接受低/中/高，数据库不变。实际：退出0，添加c001，stderr为空。
根因：add_card只检查args.risk，未在解析文件后统一校验card中的风险；load也只检查类型。
建议：新增/更新/导入共用同一schema校验，先验证再写入；加载存量库需明确兼容/迁移策略。
验收：CLI与文件来源的风险值策略完全一致；非法值明确拒绝且库哈希不变；历史非法值不会被静默改写。

### S02｜P2｜实测：未知科研字段静默丢弃

复现：metadata.md含标题、问题、“- 单位: mol/L”和风险；执行同一add --file流程。
预期：保留单位字段，或明确警告/报错以防用户误以为完整保存。
实际：退出0，添加c002，无警告；导入后数据库不存在“单位”或“mol/L”。
根因：parse_card只接收固定FIELDS，未知键直接略过；存储Schema无学科扩展字段。
建议：保留显式metadata扩展对象，导入时给字段映射/差异摘要；未知字段至少拒绝或警告，不要静默丢弃。
验收：七专业自定义条件/单位/重复/设备字段导入—导出无损；未知字段行为有文档和测试。
注意：这是“结构化字段丢失”；同样的mol/L写进现有问题字段时本轮可正常保存，两个现象不矛盾。

### S03｜P1｜静态：贡献占比要求与主规则冲突

位置：references/report-template.md:103要求“新增部分占比多少”；SKILL.md与demystify禁止按代码/模块占比判断贡献；idea-generation的“砍掉80%效果不掉则贡献可疑”“3行代码”也保留简化倾向。
根因：主规则修订没有覆盖所有模板与例子。
建议：统一改为贡献类型、差异、支持证据、适用范围；简化是验证假设的工具，不能据此推断无创新。
验收：全库检索无强制贡献百分比；对简短理论、材料发现、独立复现等案例给出同等证据标准，不按代码量评价。

### S04｜P1｜静态：不显著后改子条件结论缺少探索性限制

位置：references/sharpen.md:104建议不显著时转为某子条件有效；主文件要求不靠事后换指标制造成功。
根因：未区分事前设定的子组分析与看到结果后的探索。
建议：允许提出探索性子组假设，但明确不能作为已确认有效性；说明多重比较和独立验证需求。
验收：总体结果不确定、事后挑出一个漂亮子组的案例中，输出探索性标签，不宣称研究成功，并提出验证计划。

### S05｜P1｜静态：最小验证的时间、二分判据与实验形式过窄

位置：sharpen.md:77、85–86、92–93：能用/不能用、一个主指标+一个辅助指标、关模块作负对照、超过两周继续拆。
根因：把计算研究的低成本原型规则当成所有研究的硬约束。
建议：改为“支持/不支持/信息不足”的最小信息增益检查点；按研究类型选择对照；耗时由现象周期、设备排队、审批和重复计划决定。
验收：长期培养、老化/寿命、季节代表性、理论推导案例允许合理等待；代理实验明确不能替代最终结论；不通过事后降低证据要求赶时间。

### S06｜P2｜静态与角色观察：学科与研究类型检查表缺位

位置：现有参考主要使用dataset、baseline、module、消融及少样本例子。
根因：四种模式描述“要做什么”，缺少“本研究用什么证据判断”的第二层路由。
建议：按第5节做七专业和研究类型组合，不把医学等同机器学习、不把化学等同催化、不把电子信息等同通信。
验收：每专业至少覆盖数据研究与另一种实验/理论/仿真任务；没有任何一份专业模块时，不应宣称该专业已完整支持。

### S07｜P2｜静态：科学元数据和证据状态缺少结构

根因：九个通用文本字段无法可靠区分假设、已观测结果、来源定位、实验单位、单位和版本；“待补充”仅以可延伸方向是否为空判断。
建议：加入可选结构化字段：研究类型、证据状态、来源及定位、条件/单位、独立实验单位、对照、不确定性、数据/代码/仪器版本、未解决问题；缺失度按研究类型计算，不把“写有延伸方向”当成完整卡片。
验收：没有来源/单位/实验单位的卡片按其任务给出明确待补项；待验证建议不会出现在“已证实结论”栏。

### S08｜P2｜静态+计时：周报无界两两配对

根因：即使报告只展示每标签组合第一对，也仍遍历并存储所有候选对。
建议：预计算指纹、按标签分组、每组有界取样/分页；允许设置候选上限；先按语义/条件兼容性筛选，配对仅作线索。
验收：输出可追溯、不自配、不含完全重复；增加预设规模与内存预算的基准；达到上限明确提示截断，不能悄悄漏掉。
本轮计时不测语义配对准确率。

### S09｜P2｜静态：术语与检索源过度简化

位置：search-sources.md:27把domain shift与外部验证列作同一问题的不同术语；二者有关但不能当严格同义。source表没有按七专业研究类型细分。
建议：用“相关概念/关联检索词”而非等价词；按学科选择官方可用检索源，跨学科分别查证，保存范围、版本与可访问性。
验收：替换词不会被写成定义等价；无数据库访问时明确降级且保留未核实状态。

## 5. 面向理工科的下一版设计

### 通用核心

保留四种任务模式，并先识别：学科、研究类型、当前阶段、已有材料、真实约束。只有会改变当前判断的缺项才追问。核心输出保持：研究问题→主张→证据→不确定性→下一步；不强迫所有研究都“击败最强baseline”。

对理论、描述性、探索性、复现、方法改进、工程验证、预测、因果研究使用不同证据清单。跨学科任务同时加载相关模块，明确两侧证据要求在哪里相接。

### 七专业按需模块

|模块|最低检查范围|容易造成错误结论的情形|
|---|---|---|
|计算机|数据切分、污染/泄漏、公平资源、随机性、泛化、计算成本、代码/依赖版本|用户/时间/样本关联跨分组；单次小差值当稳健提升|
|化学|身份/纯度、计量定义、条件、独立批次、对照、表征证据、机理主张边界|单谱图推机理、单批次推可重复、产率与选择性混用|
|生物|实验单位、技术/生物重复、资源身份、批次、统计比较、因果证据链|孔数当独立样本、相关直接推因果|
|医学|研究设计选择、目标人群、时间零点、终点、缺失与偏倚、验证、治理和结论边界|预测性能推治疗效果、时间泄漏、单中心推普遍应用|
|机械|几何/材料、载荷/边界、收敛、约束、验证与实测校核、误差|单工况推工程通用性；仿真最优等于实物最优|
|能源|功能单位、系统边界、守恒、工况、时间范围、初末状态、辅助能耗|不同边界比效率；一天结果推全年；储能透支冒充节能|
|电子信息|信号/信道、带宽/功率/采样、噪声、同步、硬件参数、时延、测量条件|单点SNR比较、不公平带宽/功率、仿真直接推硬件部署|

以上是建议的基础清单，不是完整行业规范，也不代表已用真实设备或真实临床数据验收。

### 长任务执行协议

不要把“长任务”做成第五个科研主题模式，而应覆盖A–D：保存目标、约束、材料定位、已执行命令/结果、已知失败、待查问题和下一步；每个阶段设可审查检查点；恢复时读取检查点而不是假装记住全部上下文。实际实验的等待周期应记录，不能为缩短对话任务而虚构完成。跨轮恢复应单独测试。

### 版本路线

|版本建议|内容|发布条件|
|---|---|---|
|v1.1.1|统一导入校验、未知字段显式策略、清理模板冲突|新增失败用例由红转绿，现有测试保持通过|
|v1.2.0|学科/研究类型路由、七模块、完整度与证据清单|前向测试覆盖七专业不同研究类型，有专家抽查|
|v2.0.0（如破坏兼容）|结构化数据schema与迁移|旧库备份、无损迁移、失败回滚、可复现迁移报告|

这些是建议版本，当前受测源码仍为v1.1.0。本轮没有把建议直接改成已实现功能。

## 6. 下一轮如何证明“真的有效”

采用同一模型、工具权限和资料，比较“无Skill/当前版/学科版”；随机顺序、盲评输出，保留失败输出与全部任务。每专业由相应研究背景的人审查，不让生成答案的模型独自判定专业正确性。

先预设：关键证据错误、无依据新颖性断言、虚构来源、丢条件/单位、因果越界等严重错误为独立指标；再测任务适配、可执行性、少问冗余问题、达到可用计划所需时间和token。不能以篇幅长或格式全代替有效。

一个可执行的起步方案：每专业5个题目，每题覆盖A/B/C/D中的适用部分，并加入未提示错误的正常任务、理论/非改进研究、长周期任务和跨学科任务。对部分题目做3种措辞与中断恢复。数量是试验设计建议，不是统计功效保证。

验收目标须在测试前确定：如禁止编造引用、必须区分事实与假设、必须保留输入科研条件、遇到证据不足能给出信息不足；有用性和用时改进由盲评与对照测量，不能直接承诺固定百分比。

## 8. 证据与复现

- run_cross_domain.py：本轮自编并审阅的测试驱动，限定合成数据库路径；如果同名测试数据库存在会拒绝复用。
- cli-results.json：每次真实命令的argv、工作目录、退出码、stdout、stderr、耗时、预期和判定，以及源码哈希。
- 七个专业Markdown：原始题目、AI实际回应、专业意见与限制。
- temp-data：中间合成数据库与输入文件；不作为个人科研素材使用，不提交至版本库。

重新执行测试时，将整个受测源码仓库（含evaluation-stem-v1）复制到新的隔离工作区并让该副本内temp-data保持不存在，或者先修改测试驱动中的WORK指向新的空目录。不要删原始素材或原始ZIP。模拟计时包含进程开销，不能与目标Agent响应时间混淆。


诊断驱动本轮退出0表示结果文件生成完毕，不表示检查全部通过；应读取summary.failed与逐项passed。两个未符合项均按失败记录保留。probe-evidence.json另存了这两个探针的输入与实际数据库快照。
